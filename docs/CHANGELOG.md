# Teliki Signage — История изменений

---

## v2.0 — Яндекс.Диск (текущая версия)

**Дата:** июнь 2026

### Что изменилось

Полная замена бэкенда: вместо Firebase теперь используется **Яндекс.Диск** через REST API.

### Почему перешли

Firebase перестал работать в Крыму из-за геоблокировки Google-сервисов. Телевизоры в кофейнях Крыма не могли подключиться к Firebase — контент не загружался, приложение было бесполезным. Нужно было российское решение, доступное без VPN.

### Новая архитектура

- **Хранение контента:** Яндекс.Диск (облако)
- **API:** REST API Яндекс.Диска с OAuth-авторизацией
- **Структура:** `Teliki/{Кофейня}/{Экран N}/файлы + schedule.json`
- **Оффлайн-режим:** локальный кэш медиафайлов, работа без интернета после первой загрузки
- **Расписание:** `schedule.json` в каждой папке экрана, управление временем показа контента

### Преимущества v2 перед v1

| | v1 (Firebase) | v2 (Яндекс.Диск) |
|---|---|---|
| Доступность в Крыму | ❌ Заблокирован | ✅ Работает |
| Зависимость от Google | Полная | Отсутствует |
| Управление контентом | Firebase Console | Яндекс.Диск (drag & drop) |
| Стоимость | Бесплатный лимит, потом платно | Бесплатно до 10 ГБ |
| Оффлайн-режим | Частичный | Полный |
| Сложность настройки | Высокая (google-services.json, правила безопасности) | Низкая (один OAuth-токен) |
| Расписание показа | Не было | Есть (schedule.json) |

### Список изменений

- Удалены все зависимости Firebase (firebase-storage, firebase-database, firebase-auth)
- Добавлен модуль `YandexDiskClient` для работы с REST API
- Добавлен `CacheManager` для управления локальным кэшем файлов
- Добавлен `ScheduleManager` для работы с расписанием показа
- Переработан `SetupActivity` — вместо входа через Google аккаунт теперь ввод OAuth-токена и выбор папки
- Переработан `PlayerActivity` — поддержка расписания и оффлайн-режима
- Обновлены зависимости: OkHttp, Retrofit, ExoPlayer

## v1.x — Firebase (устаревшая)

**Период:** 2024 – начало 2026

### Что использовалось

- **Firebase Storage** — хранение медиафайлов (видео, изображения)
- **Firebase Realtime Database** — хранение конфигурации и списка файлов для каждого экрана
- **Firebase Authentication** — аутентификация устройств через анонимный вход
- **Google Services** — обязательная зависимость для работы Firebase

### Как работало

1. Контент загружался в Firebase Storage через Firebase Console или веб-интерфейс.
2. В Realtime Database хранился список файлов и порядок воспроизведения для каждого экрана.
3. Приложение на Android TV скачивало файлы из Firebase Storage и воспроизводило по порядку.

### Почему перестало работать

**Геоблокировка Google в Крыму.** Начиная с определённого момента, Google-сервисы (включая Firebase) стали недоступны с IP-адресов Крыма. Это привело к следующим проблемам:

- 🚫 Приложение не могло авторизоваться через Firebase Authentication
- 🚫 Не загружались файлы из Firebase Storage
- 🚫 Не читалась конфигурация из Realtime Database
- 🚫 Обновления контента не доходили до устройств
- 🚫 VPN на Android TV — ненадёжное и неудобное решение для production

### Выводы

Firebase — отличный инструмент, но **непригоден для проектов, работающих в регионах с ограниченным доступом к Google-сервисам**. Для таких случаев необходимо использовать альтернативные решения с серверами в России.
